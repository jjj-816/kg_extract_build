# 共享上下文批量关系抽取设计

## 目标

在不牺牲实体中心关系抽取可解释性的前提下，将现有“每个对齐实体检索后立即调用一次 LLM”调整为“全部实体先检索、按共享证据严格分组、组内上下文去重后批量调用”。不相关实体保持单实体批次，避免为了减少调用而强行合并。

## 方案选择

项目保留两种可选关系抽取策略：

- `single_entity`：现有逐实体流程，作为论文实验基线。
- `shared_context_batch`：默认优化流程，先统一检索，再按共享证据分组抽取。

没有采用纯文本切片统一抽取，因为它可能降低长尾实体和跨切片关系的召回率；也没有采用固定每 3–5 个实体分组，因为无关实体会相互干扰。

## 数据流

1. 实体抽取和实体对齐保持不变。
2. 对全部对齐实体执行检索，保存每个别名的命中句、`sentence_index`、匹配类型和分数。
3. 已命中三元组缓存的实体不再参加检索和分组。
4. 没有检索证据的实体直接产生空结果，不调用 LLM。
5. 使用完全相同的 `sentence_index` 计算实体间重叠系数：

   ```text
   overlap(A, B) = |A ∩ B| / min(|A|, |B|)
   ```

6. 只有达到阈值的实体才能进入同一批次。新实体必须和批次内每个已有实体都达到阈值，避免 A-B、B-C 相关但 A-C 无关的传递合并。
7. 批次同时受到最大实体数和最大去重上下文字符数限制。无法安全合并的实体形成单实体批次。
8. 批次证据按 `sentence_index` 去重并保持原文顺序。每个实体单独保存允许引用的证据编号。
9. 多实体批次调用一次 LLM；单实体批次继续走现有 `generate()`，保证基线行为和缓存兼容。
10. 批量结果按 `head` 分配回实体，继续使用现有 Schema 校验、三元组纠错、MySQL 持久化和调试快照。

## 默认参数

- 策略：`shared_context_batch`
- 每批最多实体：3
- 最小重叠系数：0.4
- 每批去重上下文最大字符数：8000

参数进入 `PipelineConfig`、Streamlit 高级设置和实验配置快照。运行时允许切回 `single_entity` 生成严格基线。

## 提示词结构

批量提示词只展示一次去重证据：

```text
【证据句】
[S12] 井口安装防喷器……
[S13] 防喷器用于控制井喷……

【目标实体】
- head=井口；head_type=设施；证据=S12；允许关系=……
- head=防喷器；head_type=设施；证据=S12,S13；允许关系=……
```

模型只能为目标实体输出三元组，且每条关系的 tail 必须出现在该实体允许引用的证据中。每个实体仍应用自己的允许关系和尾实体类型。

## 持久化和可复现性

- 原始逐实体检索结果继续写入 `kg_retrieval_result`。
- 一个批次只产生一条 `kg_llm_call`，同批次三元组共享其 `source_llm_call_id`。
- LLM 调用元数据记录批次实体、证据编号、分组阈值和批量策略。
- 每个实体仍生成可被现有缓存读取的调试 JSON；其中记录批次 ID、完整提示词、原始响应和该实体分配到的三元组。
- 实验快照记录所有批量参数，确保论文实验可以复现。

## 错误与取消

- 检索阶段和每个批次调用前后检查取消令牌。
- 批量调用失败时，该批次所有实体记录失败调用，但不会伪装成成功空结果。
- 单批解析异常只影响该批次，文档最终状态应反映关系抽取失败，而不能静默完成。
- 缓存实体、无证据实体和正常批次最终合并为统一的 `raw_triplets`。

## 测试范围

- 重叠系数、严格分组、无关实体单独成组。
- 组内按句子编号去重及实体到证据编号映射。
- 最大实体数和最大上下文字符数拆批。
- 批量提示词不重复证据，包含每个实体独立 Schema。
- 一次批量响应按 head 正确拆分并共享 LLM 调用 ID。
- `single_entity` 保持原行为。
- Pipeline 先完成全部检索再发起批次调用。
- Streamlit 参数、快照脱敏、取消、缓存、失败状态和完整回归测试。
